# Shared Chewie and Jango dataset protocol

## Goal

Provide one installable Python package for comparing methods on Chewie_CO_2016 and Jango_ISO_2015. The package owns loading, sample identity, binning, folds, training-only noise, and access to each data partition. The caller drives the evaluation sequence, fits the model, declares the search space, and supplies a frozen scorer. The examples show the full sequence and report format. V1 supports within-session experiments and explicitly specified Day-0 → Day-K pairs.

| Local archive and session selection | The Chewie archive contains 12 MAT files, including 2016-09-27, which the existing ERDiff list skips. Seven Jango sessions are present in the shared workspace. The package discovers available sessions and records the explicit selection used for each benchmark. |

The dataset release identifies Chewie as an unloaded center-out reaching task and Jango as an isometric wrist force task. Chewie's default target is XDS `curs_v`. Jango's default target is XDS `force`, in recorded units. Preserve the target name and units in reports. Compare methods on the same session, fold, and target, and report per-dataset estimates. [Dryad dataset and methods](https://doi.org/10.5061/dryad.cvdncjt7n)

## Package design

Use one XDS v7.3 reader with small dataset specifications for the target field and task metadata. Two independent loaders would keep binning and leakage rules duplicated. A reader tied to existing model repositories would also make data preparation depend on their experiment code and historical preprocessing. The proposed standalone package uses a shared NumPy and h5py pipeline and a `src/spike_datasets` layout.

### Binning and split groups

- Use a **20 ms** default bin in both views. A bin is a complete, half-open native-sample span. Validate the requested width against the native timebase. Sum spike counts into integer arrays and average the named behavior stream in each bin. Preserve raw indices, start times, channel order and IDs, and behavior masks. Mark a behavior axis invalid if any native sample for that axis is nonfinite in the bin. Valid spike counts are finite, nonnegative integers.
- **Trial view** returns variable-length trial arrays from recorded trial start to end, with each bin anchored to the first native tick at or after trial start. Keep original trial IDs and annotations. Drop incomplete tails and keep partially overlapping trials in the same split group. Default eligibility uses valid recorded bounds and at least one complete bin, independent of outcomes and behavior values. Go cues and outcomes remain metadata.
- **Fixed-time view** returns a time-ordered stream on one session-wide grid. Drop any fixed bin spanning two split groups and drop incomplete session tails. Record dropped spans. Downstream history windows may use consecutive bins from one group.
- Form common split groups from the transitive closure of all valid recorded trial intervals, including intervals shorter than a bin that might bridge other trials. Keep components containing at least one trial-view bin as split groups. Treat short-only components and native times without usable trial bounds as gap time in the fixed-time view. Gaps follow the preceding retained group, with leading and trailing time owned by the first and last retained groups. Count and report trials omitted from the trial view. Both views use the same group membership. Fail before signal reads if a planned partition has zero bins in the requested view.
- The default protocol applies zero smoothing and zero neural lag. Eligibility, channel selection, and feature extraction must preserve split isolation. If a downstream method uses an offset, resampling filter, smoothing, or a window, every raw sample it depends on must come from its assigned group and partition.

### Evaluation and isolation

- Default to **three outer folds**, with seed **42** for deterministic shuffling of whole groups. Each group is held out exactly once. Inner validation uses **two grouped folds** within each outer held-in set. Preserve fold IDs and use the same manifest across methods. Chronological mode uses an earliest train prefix and a latest held-out suffix. The proposed default suffix is `ceil(n_groups / 3)` whole groups. For tuning, use the latest `ceil(n_held_in / 3)` held-in groups for inner validation with an earlier fit prefix. Fail with a clear error when a requested split would be empty. Chronological splits test future-time performance. Shuffled folds test generalization across held-out groups from the same recording.
- The development path reads only the signal slices assigned to its fit or validation partition. The reader can inspect file schema, unit IDs, timestamps and trial bounds to construct the plan. Validation, early stopping, model or channel selection, normalization, and noise calibration get their inputs from held-in data only. In an inner fold, fit learned state on inner-fit rows and apply it frozen to inner validation. After a choice is locked, refit from scratch on the full outer held-in set and score the held-out set with that frozen state. The examples complete selection for every fold and compared arm before revealing any final scores. The scoring interface requires a matching locked selection, and callers are responsible for keeping final scores out of all later tuning in the same benchmark.
- A fixed pair specifies a source session and a strictly later target session from the same dataset before fitting. Use independently planned session groups and pair the manifests by fold index. Within-session tuning and cross-day source tuning use the relevant held-in development partitions. Zero-shot transfer reads no target signal for development. If adapting, read only target held-in spikes. Select adaptation settings on target held-in inner validation with a neural-only criterion, or predeclare them from source development. Open target held-out behavior for scoring after the source and optional adaptation choices are frozen. Preserve session-specific unit IDs so callers can explicitly declare and fit any cross-day mapping.
- Manifests record source IDs and version, session and group IDs, assigned raw intervals, view and bin configuration, split seed, boundaries and exclusions, and a protocol schema version. Record model seed, selected settings, target, and manifest ID in benchmark output. Source checksums may be computed during data acquisition and recorded separately from development. Development must never scan held-out signal arrays to compute IDs, perform validation, or fit statistics. Report fold sample counts and paired method differences, with clean targets and the metric aggregation rule visible.

### Small additive noise

Enable training augmentation with the proposed default **0.02 × training per-unit standard deviation** and a clean baseline at `0.0`. Accept finite fractions from **0.0 to 0.05**. For every unit, fit the population standard deviation on clean fit bins in that exact session, fold, and view. Use zero scale for constant units. Use a seeded standard normal draw bounded at ±3 before multiplying by the fitted scale and configured fraction. This caps the default absolute perturbation at 0.06 training standard deviations per unit. Generate one perturbation per value in canonical bin order when the fit view is materialized, then use the same view across epochs. Batch size or order cannot change the samples. Keep raw counts unchanged and return augmented float features for training. Models that require nonnegative integer count observations use the clean counts in their likelihood. Validation, held-out inputs, and every behavior target remain clean. Use a dedicated, recorded noise seed independent of split and model seeds.

The bin width, inner split size, chronology cutoff, and noise scale are proposed starting defaults. Choose noise strength before outer scoring, or tune it through held-in validation with a clean control. Confirm the effect of the proposed scale on held-in data before making claims about model performance.

## Public release

Use synthetic XDS fixtures for CI and make smoke tests on acquired datasets an explicit local command. Document the dataset citation and acquisition steps. Keep recordings, archives, weights, caches, absolute machine paths, and experiment outputs out of Git and package builds. Record the maintainer-approved code license and keep upstream notices when reusing licensed code. This stage delivers the design and implementation backlog for review.
